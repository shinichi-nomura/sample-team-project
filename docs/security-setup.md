# セキュリティ修正の公開手順

コードのマージだけでは設定は完了しません。必要なキーを登録してから手動公開してください。
秘密のキーをチャット・ソース・PR・スクリーンショットに貼らないでください。

## 1. microCMS

1. 対象サービス `tokimeki-jinja` の管理画面でAPIキーの権限を確認します。
2. 新しいキーを作り、`posts` のGET（読み取り）だけを許可します。POST/PUT/PATCH/DELETEや他APIの権限は付けません。
3. GitHubの Settings → Secrets and variables → Actions → New repository secret で、名前を `CMS_API_KEY`、値を新しいキーとして登録します。
4. 新構成の公開を確認後、古いキーを無効化・削除してください。過去のGit履歴やブラウザーのキャッシュに残っているため、コードから削除するだけでは完了しません。
5. 古いキーに書き込み権限があった場合は、その権限を先に外すかキーを直ちに無効化してください。記事と操作履歴も確認します。旧サイトの記事表示は新構成の公開まで止まる可能性があります。

権限の詳細: https://document.microcms.io/content-api/x-microcms-api-key

## 2. 無料のCloudflare Turnstile

1. 運用者が管理するCloudflareアカウントにログインします。
2. Turnstileでウィジェットを追加します。対象ホスト名は `mizu-tokimeki.com`、モードはManagedを選びます。
3. DNSやネームサーバーを変更したり、サイトをCloudflareへ移転したりする必要はありません。
4. 発行されたSite keyをGitHub Secretsの `TURNSTILE_SITE_KEY` に、Secret keyを `TURNSTILE_SECRET_KEY` に登録します。
5. 実運用のキーを使ってください。公式のテスト用キーは本番に使いません。

Site keyは訪問者へ渡してよい識別子です。Secret keyはサーバー内だけで使用します。
無料プランの条件: https://developers.cloudflare.com/turnstile/plans/

## 3. 公開と動作確認

- 既存のFTP用3項目に加え、上記3項目が揃ったらPRをマージして Publish website (manual) を実行します。
- 設定が空欄なら転送前に停止します。FTP用Secretsは変更しません。
- 公開処理がメモリー上で `pages/site-config.php` を生成し、FTPSでサーバーへ送ります。Gitには保存しません。
- 設定ファイルはPHPとして実行され、直接アクセスには404を返します。PHPを無効化したり、拡張子を変更したバックアップを公開フォルダに置いたりしないでください。Base64は暗号化ではありません。
- PHP 8.2以上とcURL拡張が必要です。CMS・Turnstileへの外向きHTTPS通信も必要です。応答タイムアウト時は確認を省略しません。
- トップのお知らせ、イベント詳細、近況報告詳細が表示されるか確認します。太字・リンク・画像などの記事書式は許可しますが、iframeや任意のスクリプトは表示しません。
- CMS一覧は従来どおり最新100件が対象です。60秒キャッシュし、この範囲外の古い記事への直接リンクも個別取得で維持します。個別取得は1分間に異なる100件までとし、存在しないIDへのアクセスもキャッシュします。
- お問い合わせ画面でTurnstileの確認を完了し、ご自身のアドレスでテスト送信して受信まで確認します。
- 外部確認サービスに接続できない場合、入力は保持し、再試行ボタンと直接メールでの連絡先を案内します。
- 公開後に古いmicroCMSキーを無効化して初めて、漏れていたキーへの対処が完了します。

## 制限と運用

メールの送信制限に加え、トークン発行・失敗送信も同一IPから1時間120回、全体3000回までとしています。
Turnstileは自動投稿を減らす対策であり、攻撃を完全に防ぐ保証ではありません。大規模なアクセス集中はサーバー側のWAFや制限も確認してください。
CMS中継は任意URL・下書きキー・検索条件を受け付けず、公開済みの指定記事フィールドだけを返します。
DOMPurifyは `js/vendor/purify.min.js` の3.4.17を使用しています。公式のセキュリティ更新に追従してください。

## 戻す場合

新しい設定ファイルはrevertしてもサーバーに残ります。設定やPHPの不要ファイルは手作業で削除してください。
旧JSへ戻すとAPIキーの公開が再発するため、単純なrevertで旧構成へ戻す運用は避け、修正して再公開してください。
