# お問い合わせフォームの管理

## 仕組み

`pages/contact.html` が入力画面、`js/main.js` が画面上の検証・送信表示、
`pages/contact-send.php` が入力の再検証とメール送信を担当します。
受信先と送信元は `info@mizu-tokimeki.com` に固定しています。
訪問者のアドレスは Reply-To（返信先）だけに使います。
サーバー内の mail() を利用するため、POP・IMAP設定やメールパスワードは不要です。
返信は受信したメールに対して通常のメールソフトから行います。自動返信は送りません。

Turnstile導入後のキー登録・公開手順は [security-setup.md](security-setup.md) を先に確認してください。

## 初回の設置と確認

1. サーバーのPHP設定をサポート中の8系（8.2以上）にします。
2. PRをマージ後、Publish website (manual) を実行します。PHPファイルも対象です。
3. HTTPSの本番お問い合わせページを再読み込みします。GitHub PagesやHTMLの直接表示ではPHPは動きません。
4. ご自身のメールアドレスと「送信テスト」と分かる内容で送信してください。
5. `info@mizu-tokimeki.com` の受信箱・迷惑メールを確認します。氏名・日本語本文・任意項目の文字化け、返信先も確認してください。
6. 画面の受付表示だけでは到着確認になりません。mail()の成功はメールサーバーが受け付けたことを表します。

メールが届かない場合は運用開始せず、お名前.com側の送信制限・迷惑メール・PHPエラーログを確認します。
必要なら認証SMTP方式に変更しますが、パスワードをGitHubやチャットには記載しないでください。
今回の作業では本番へのアップロードと実際のメール送信は行っていません。

## 日常の管理

- 送信先を変えるときはPHP先頭の CONTACT_TO と CONTACT_FROM を確認します。
- サイトのドメインを変更するときは CONTACT_ORIGIN も変更します。
- 同じ送信元IPは60秒に1回、1時間5回、サイト全体は1時間100回までです。失敗した送信の試行も数えます。
- 同じネットワークの利用者は制限を共有します。大量アクセス対策として万能ではありません。
- 制限情報はPHPの一時ディレクトリに保存し、1時間経過分を次の送信時に削除します。問い合わせ本文や生IPは保存しません。
- セッションCookieは送信の検証と二重送信防止に使います。Cookieを拒否すると送信できません。
- 入力内容は通信失敗時に画面へ残ります。受付完了時のみ消します。
- エラーログには `Contact failed:` と例外の種類のみを記録します。本文・パスワードは記録しません。
- PHPの更新後やサイトの修正後はテスト送信し、受信まで確認してください。

## 学習と開発

PHPの `validate_contact` は入力確認、`contact_message` はメール本文作成、
`contact_rate_limit` は連続送信制限、`handle_contact` は受付全体です。
テストは `php tests/contact_test.php`、構文確認は `php -l pages/contact-send.php`。
テストはメール送信を実行しません。

## 元に戻す場合

不具合があればこのPRをrevertして再公開し、サーバー側の `pages/contact-send.php` も削除してください。
公開処理は既存ファイルを自動削除しないため、revertだけではPHP受付がサーバーに残ります。
