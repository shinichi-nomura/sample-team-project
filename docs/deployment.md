# お名前.comへの手動公開

## 初回準備

Repository secretsに `FTP_SERVER`、`FTP_USERNAME`、`FTP_PASSWORD` を登録します。
FTPアカウントの接続先ディレクトリは既存サイトの `public_html/mizu-tokimeki.com/`。
このアカウントから見える `/` に css・images・js・pages があることを確認してください。
サーバー側のPythonは不要です。転送プログラムはGitHub上で動きます。

## 公開手順

1. 修正PRを確認してmainへマージします。
2. 初回はFFFTPで既存サイトのバックアップをパソコンへ取得してください。
3. GitHubの **Actions → Publish website (manual) → Run workflow** を開きます。
4. Branchを **main** にして **Run workflow** を押します。この操作で本番を更新します。
5. 緑の成功表示を確認し、https://mizu-tokimeki.com/ をPC・スマホで確認します。

mainへのマージだけでは転送しません。FFFTPとの同時更新は避けてください。
実行開始時のmainのコミットを転送します。実行後にマージした変更は次回の実行対象です。

## 転送範囲と制限

- index.html と css・images・js・pages 内の公開用拡張子のファイルを毎回転送します。
- .git、隠しファイル、README、スクリプト、パスワードなどは転送しません。
- FTPS Explicit（21番）で証明書を検証し、ファイル通信も暗号化します。
- ファイルごとに一時ファイルへ転送してから置換します。サイト全体の一括切替ではありません。
- error、.htaccessなど、サーバーだけにあるファイルは削除しません。
- GitHubで削除・改名した古いファイルもサーバーに残ります。不要な公開ファイルは別途確認して削除してください。
- 失敗時は一部だけ更新済みの場合があります。原因解消後に再実行してください。
- 戻す場合は変更を取り消すPRをmainへマージして再実行、またはバックアップをFFFTPで復元します。

この設定は静的サイト用です。お問い合わせの送信処理を追加する際は、転送対象と秘密情報の配置を別途設計します。
